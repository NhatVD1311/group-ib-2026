ATTACK RECONSTRUCTION The earliest access to the infrastructure was received no later than December 10, 2020. On 3 compromised servers, the nbtscan utility, a program for scanning IP subnets to find open resources by scanning for NetBIOS Name servers, was unpacked and launched. Since network scanning as part of the attack is carried out already at the post-operational stage, it can be argued that the initial penetration into the corporate perimeter was carried out earlier than the above date. At the initial stage, in addition to regular system utilities, the attackers used, at a minimum, pscp and plink console applications, which are clients for working with individual network protocols (for example, Telnet, SSH, SCP), presumably for tunneling and uploading individual data. All the tools they used were located in the C:\Windows\Temp\ directory on the compromised servers with slightly different file names. In the process of moving around the network, the attackers used mimikatz and secretsdump - utilities that allow you to extract user passwords in various ways, including from local accounts and cached domain accounts, as well as LSA secret keys. Later, as additional tools, attackers began to use utilities such as PsExec (from the SysInternals package) for remote command execution, and portscan for network analysis, searching for network devices and their open ports. Moreover, the list of tools used regularly expanded as the attack developed. So, almost until mid-May 2021, attackers performed a similar series of actions: actively moving around the network, regularly scanning it and collecting additional authentication material. On August 13, 2021, attempts to exploit the vulnerability CVE-2021-31207 were recorded for the first time on one of the servers, which is the final one and is applied after the successful exploitation of the first two of the chain of vulnerabilities called ProxyShell (CVE-2021-34473, CVE-2021-34523, CVE-2021- 31207). These vulnerabilities allow interacting with vulnerable servers with the highest local privileges and executing arbitrary code on the server, including downloading various files, including web shells. Their placement on the OWA service allows an attacker to gain a foothold in the company's network and provide remote access to compromised hosts. As part of the exploitation of the chain of listed vulnerabilities, on August 16, 2021, the privileged domain Administrator account was assigned the Mailbox Import Export role (Fig. 1) for further export of encoded web shells previously placed in user drafts to publicly accessible directories of Exchange mail servers (Fig. 2). Similar actions to upload web shells were periodically performed until March 12, 2022. As part of the next stage, on March 05, 2022, the \Microsoft\Windows\CertificateServicesClient\DnsPolicyTask task was created on the compromised attacking station with a load in the form of the C:\Windows\system32\DnsPolicyTask.exe file and parameters for its execution in an obfuscated form. This file is a renamed PowerShell shell executable, and the payload is a loader of PowerShell scripts for their subsequent execution through one of the following links: hXXps://sessions[.]dns05[.]com/latest/list hXXps://latest[.]sessions[.]linkpc[.]net/news/list Also, through the use of the PowerShell shell, the shellcode loaders were executed on March 12, 2022. Bypassing AMSI and PowerShell ScriptBlock logging, each script executed ran the contained meterpreter shellcode, which downloaded shellcode from web links with a URI containing an arbitrary character sequence like hXXps://176[.]223[.]111[.]176/news/{RANDOMSEQUENCE} and passed control to it (an example of such an event with an obfuscated load is shown in Figure 3). On March 24, 2022 at 12:02:30, malicious activity was detected for the first time on yet another workstation. At the specified time, the English.hlp, goopdate.dll, vm3dService.exe files were created in the C:\ProgramData\vm3dService directory. The last executable file listed uses the goopdate.dll dynamic-link library (DLL hijacking) hijacking technique for a legitimate software file from Google Inc. vm3dService.exe (originally named GoogleUpdate.exe). Running vm3dService.exe loads goopdate.dll, which decrypts and decompresses the payload called RCSession from the English.hlp file. The payload in the form of a DLL is loaded directly into memory and injected into the %System32%\msiexec.exe processes launched by the backdoor. RCSession provides remote access to a compromised system. Control server addresses: package[.]update-pfsense[.]com:53 package[.]update-pfsense[.]com:443 According to the configuration, any of the available protocols can be used to interact with the control server: TCP, UDP, HTTP/HTTPS. Depending on the user's rights, the backdoor either installs itself as a vm3dService (vm3d SVGA Helper Service) system service or registers its executable file in the autorun section of the system registry. On March 24, 2022 at 12:02:30, the specified service was installed on one of the workstations. At the command of the control server, this backdoor can not only send information about the system and execute Windows shell commands, but also track keyboard input (perform keylogger functions), information about pressed keys, windows, and processes. The collected information is written in encrypted form to the following report file: %ALLUSERSPROFILE%\vm3dService\{USER_NAME}.prx где USER_NAME – имя пользователя. Subsequently, the behavioral pattern continued to be fairly uniform: moving from host to host using system utilities, attackers regularly established themselves on new hosts using one of the methods described above, leaving behind the possibility of remote connection and activity monitoring on compromised machines. PowerShell scripts were occasionally executed on already captured hosts in the form of files using commands like: powershell -ep bypass -f A[.]ps1 It is not possible to fully establish the purpose of all executed files due to insufficient logging. However, based on the history of commands entered (PSReadline\ConsoleHost_history.txt) from the workstation, the only script executed on it, rdpu[.]ps1, allowed viewing a list of remote machines that had previously been accessed via BOR, together with the account used to create this connection. As mentioned earlier, the most frequently used directories by attackers were C:\ProgramData and C:\Users\Public. Downloading malicious files was most often done in archives, which were then unpacked into the current or explicitly specified subdirectory of the specified directories: 7z.exe x msedgeupdate.7z -o. To unpack, the attackers used the 7-71 archiver previously installed on the compromised machine, but sometimes they additionally downloaded its executable file to the current working directory, for example, c:\programdata\microsoft\appv\7z.exe. After the immediate launch, tasks and services are actively used for pinning. They are created both directly on the current host and on remote machines using the following commands: schtasks /create /tn Microsoft_edgeup /tr "C:\ProgramData\Microsoft\EdgeUpdate\msedgeupdate.exe" /sc onstart /s HOST /u Svc-OM_Action /p PASSWORD /RU SYSTEM sc \\HOST create "Microsoft_edgeup" binpath= "C:\ProgramData\Microsoft\EdgeUpdate\msedgeupdate.exe" start= auto displayname= "Microsoft_edgeup update server" Tasks are installed with NT AUTHORITY/SYSTEM rights, which allows the program to run with the highest local privileges. Interaction with previously created objects is carried out similarly through system utilities and often explicitly specified credentials, which also change over time: sc start Microsoft_edgeup sc \\HOST start Microsoft_edgeup schtasks /run /tn MicrosoftSeting /f schtasks /run /tn Microsoftdsync /s HOST /u Svc-OM_Action /p PASSWORD In some cases, more sophisticated methods were used, for example, creating tasks used exclusively to start services: schtasks /create /tn sslinfo /tr "sc start 'WinDeviceSyncs'" /sc onstart /s HOST /u Svc-OM_Action /p PASSWORD /RU SYSTEM In addition to the above, attackers regularly covered their tracks, not only by deleting previously created services, services and files, but also by terminating the processes they themselves spawned, including using WMIC, the command line interface for Windows Management Instrumentation: wmic /node:HOST /user:Svc-OM_Action /password:!Q2w3e4r process call create "cmd /c taskkill /im dllhost.exe /f" One of the methods for obtaining credentials was to disable the protection of credentials through the appropriate registry keys (enabling Restricted Admin Mode).
